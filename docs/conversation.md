# 会話の使い方

Botとは、ふつうの発言で話します(スラッシュコマンドは使いません)。返事には話し手のAPIキー・モデル・Discordの権限を使います。先に [/settings](settings.md) でキーと言語モデルを登録してください。

## 話しかける

- Botをメンションすると、必ず返事をします。Botの発言への返信も、メンションをオンにしたままなら同じです。
- メンションをオフにしてBotの発言に返信したときは、必ずは答えません。Botが寝ていても、下の「Bot宛てか」の判定をして、宛てだと判断したときだけ答えます(答えるとBotが起きます)。判定には返信先の発言も見せます。
- 一度返事をすると、そのチャンネルでBotが5分間起きています。起きている間は、メンションのない発言も「Bot宛てか」を判定して、宛てだと判断したものに答えます。判定には発言した人の判定モデル(用途別の「宛先の判定」があればそちら)とその人のAPIキーを使い、確信度が0.7以上のときだけ答えます。
- 最後の返事から5分たつと眠ります。また話すにはメンションします。
- 会話はチャンネルごとです。スレッドは別のチャンネルとして扱います。サーバーごとにも分かれていて、DMでは話せません。
- Botの発言とWebhookの発言には答えません。

設定を済ませていない人の発言は判定もせずに無視します。その人がメンションしたときだけ、`/settings` への案内をDMで1回送ります(起きている間に1回まで)。DMを受け取らない設定なら、何も送りません。

## 返事のしかた

- 直前の30件を文脈として読みます。足りなければ道具で履歴を読み足し、1回の返事で500件まで読みます。
- 作業の途中で、道具を使う前の一言をそのまま投稿します(1回の返事で6件まで)。
- Botが答えている間に同じ人が書き足した発言と、答えている発言の編集は、同じ返事に取り込みます。
- 長い返事や区切りのある返事は、何件かの投稿に分けます。
- 画像は1回の返事に10枚まで付けられます。絵文字やスタンプの登録に使う画像は数えず、1回の返答で用意できる画像は100枚までです。

リアクションのモデル(用途別の「リアクション」、なければ判定モデル)があると、文で答えるまでもない発言には絵文字だけで返します。Botの発言に付いたリアクションは、24時間以内なら返事として扱います。OKやNGの意味だと判断すれば、その続きをします。

1回の返事で道具を使えるのは12手順までです(`compile_wasm` を使うと24手順)。上限に来たら「続ける」「ここで終える」のボタンで聞きます。聞くのは3回までです。

## 変更案と確認ダイアログ

Botがサーバーを変えるのは、確認ダイアログで本人が「実行」を押したときだけです。会話の中でBotが直接書き込むことはありません。

1. Botが変更案(Plan)を作ります。Planは「前提の状態」と「操作の並び」だけのデータです。
2. 決定的なコードが形・操作の対応表・話し手とBotの権限・ロールの上下を確かめます。通らなければ案は出ません。
3. チャンネルに確認ダイアログが出ます。押せるのは依頼した本人だけです。
4. 「実行」を押すと、実行の直前に前提と権限を Discord から取り直して、案を出したときと同じことをもう一度確かめてから書き込みます。案を出してから押すまでの間にロールや権限が変わっていれば、何も書き込まずに止まります。確かめるのは、話し手とBotの権限・ロールの上下、案が見せたチャンネルを話し手がまだ見られること、一緒に登録するルールの allow に要る権限を話し手がまだ持っていることです。長い変更では、途中でも30秒ごとに権限を取り直します。

ダイアログには次のボタンがあります。

並びは上から、内容(ルールの返事の見せ方の選択はそのルールの下)、切り替えのボタン、区切り線のあとに期限と実行などのボタンです。

| ボタン | 働き |
|---|---|
| 実行 | 変更を実行します。戻せない操作が重いときは、対象の名前か件数を入力します([確認の決まり](operations.md#確認の決まり)) |
| 修正 | どう直すかを書くと、Botが案を作り直して同じダイアログに出します |
| 取り消し | 案を取り下げます |
| 出し直す | 取り消した案、期限が切れた案、前提が変わって止まった案を、今の状態で出し直します |
| 再開 / 復元 / そのまま | 途中で失敗したときに出ます。残りを続けるか、済んだ分を戻す案を出すか、そのままにするかを選びます |
| 概要 / コード / 詳細 | 見せる内容を切り替えます。コードは、コードから作った案とルールがあるときに出ます。既存のルールを直す案では、前の版との差分(`+` 足した行、`-` 消した行)を出します |
| JSONを見る | Planをそのまま見ます |

承認を待つのは5分です。過ぎると取り消しになります。

コードから作った案には、別のAIが書いた説明が付きます。このAIは依頼を見ず、コメントを除いたコードと操作の表だけを読みます。

既存のルールを直す案では、前の版からの変更を箇条書きで出します。コードの変更は、別のAIが前の版と新しい版のコードだけを読んで書きます(コメントは除きます)。きっかけ・許す操作・params・上限の変更は、Botが比べて足します。コードが同じならAIは呼びません。変更を書けなかったときは、前の版と新しい版の説明を並べます。

## 読み取りの範囲

BotはAdministrator権限を持ちますが、読み取りは「このチャンネルを見られる全員が読めるもの」に絞ります。チャンネル・メッセージ・検索の結果は、この範囲の外を含みません。

範囲の外のものは、返事の違いからも分からないようにしています。

- 検索は該当の総数を返しません。Discord の総数には、範囲の外(非公開スレッドなど)の該当も数えられているからです。範囲の外の該当を除いたうえで、先頭から順に詰めて返します。1回で返るのは25件までで、25件そろったときは結果の先頭に「続きがあります」と出し、続きの読み方を添えます。時刻順(既定)では最後に表示したメッセージのIDを `max_id`(古い順なら `min_id`)に渡して続きを読むので、深さの制限はありません。関連度順は一番それらしいものを数件見つけたいときだけに使い、数える・全部挙げるときは時刻順にするよう、Botに指示しています。関連度順の続きは `offset` で読みます。`offset` で読めるのは先頭から200件までです。
- 存在しないチャンネルと、範囲の外のチャンネルは、同じ言い方で断ります。
- 変更案のステップが範囲の外のチャンネルを使うときは、そのことだけを伝えます。そのチャンネルがあるか、だれがどの権限を持つかは答えに出ません。
- サーバーのイベント(`/scheduled-events`)は、範囲の外のチャンネルのものを除きます。

答えるのにこれでは足りないとき、Botは話し手に読み取りを広げてよいかを聞きます。

- 「毎回確認する」(既定): 話し手だけが押せるボタンで聞きます。2分で取り下げます。
- 「常に許可する」: 聞かずに広げます。

広げても、話し手本人が見られる範囲までです。広げるのはその返事の間だけです。設定は [/settings のハーネス](settings.md#ハーネス) で変えます。

ルールは別の範囲で読みます([ルール](rules.md#読み取りの範囲))。

## Botが使う道具

応答のエージェントは次の道具を使います。どれもBotが自分で選ぶので、頼むときに名前を言う必要はありません。

| 道具 | 働き |
|---|---|
| `read_messages` | チャンネルの履歴を新しい順に100件まで読む。前後をたどれる |
| `search_messages` | サーバー内を検索する(本文・投稿者・チャンネル・メンション・添付の有無。総数は返さない) |
| `list_channels` | 読める範囲のチャンネルの一覧 |
| `find_members` | 名前・ニックネームの前方一致でメンバーを探す |
| `run_code` | 読み取り専用の JavaScript で集計する([JavaScript の API](js-api.md)) |
| `view_images` | メッセージの画像を見る(モデルが画像を読めるとき) |
| `render_math` | TeX の数式を画像にする |
| `convert_image` | 画像の大きさ・切り抜き・回転・形式などを変える |
| `judge` | 判定モデルで分類・判定・点数付けをまとめて行う(判定モデルがあるとき) |
| `propose_plan` | 変更案とルールを出し、確認ダイアログを投稿する |
| `list_rules` / `rule_runs` | 話し手のルールと、その実行履歴を見る |
| `run_wasm` | Wasm モジュールを登録せずに1回動かす([Wasm](wasm.md#一度だけ動かすrun_wasm)) |
| `list_wasm` / `register_wasm` | 話し手の Wasm モジュールの一覧と登録 |
| `wasm_language_guide` / `compile_wasm` | ソースを Wasm にコンパイルする(コンパイラがあるとき、[言語と SDK](languages.md)) |
| `read_docs` | このドキュメント(docs/)の目次・文書・見出しを読む、言葉で探す。Botの使い方を聞かれたときや、ルール・コード・Wasm を書く前に決まりを確かめるときに使う(コード用のエージェントも使う) |
| `widen_read` | 読み取りを広げる許可を求める |
| `web_search` / `web_fetch` | Webを検索する、ページを読む(Webツールを使う設定のとき) |

用途別の「コード」モデルを選ぶと、`run_code` と変更案・ルールのコードは別のエージェントが書きます。応答のエージェントは何をするコードかを文で頼み、コード用のエージェントは試しながら書いて提出します。ルールが何件かあれば、ルールごとに並行して書きます。
